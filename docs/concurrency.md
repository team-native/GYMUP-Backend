# 도메인 테이블과 동시성

## 테이블 경계

| 도메인 | 테이블 | 핵심 제약 |
| --- | --- | --- |
| 사용자 | `user_profiles`, `user_settings` | 사용자별 프로필·설정 키 |
| 루틴 | `routines`, `routine_exercises` | 루틴 운동 순서 중복 방지, 운동 항목을 별도 행으로 저장 |
| 운동 기록 | `workouts`, `workout_sets` | 사용자당 진행 중 세션 하나, 세션 내 운동/세트 번호 유일 |
| 목표·보상 | `goals`, `weekly_goals`, `rewards` | 사용자당 활성 목표 하나, 운동별 보상 하나 |
| 휴식 | `rest_timers` | 운동당 활성 타이머 하나 |
| 사진 | `progress_photos`, `photo_jobs` | 운동/사진 소유 관계와 작업 상태 분리 |
| 아바타 | `avatar_items` | 사용자별 해금 상태 |

기존 `documents` 데이터는 점진 이전을 위해 읽기 호환으로 남겨 둡니다. 레거시 레코드를 읽으면 같은 트랜잭션에서 새 도메인 테이블로 승격하고, 신규 쓰기는 도메인 테이블에만 기록합니다. 사용량을 확인한 뒤 별도 마이그레이션으로 레거시 테이블을 제거해야 합니다.

## 동시성 규칙

- 업데이트 전에 도메인 행을 `SELECT FOR UPDATE`로 잠급니다. 세트 기록, 루틴 변경, 목표 완료, 휴식 연장 같은 변경은 한 세션의 트랜잭션 안에서 처리합니다.
- 운동 세션의 `version`은 변경마다 증가합니다. 완료 요청은 최신 `expectedVersion`을 보내야 하며, 이전 버전이면 `409 WORKOUT_VERSION_CONFLICT`를 받습니다.
- 부분 유일 인덱스가 사용자별 활성 운동 세션, 활성 목표, 운동별 활성 휴식 타이머를 DB에서 한 개로 제한합니다.
- `workout_sets`의 `(workout_id, exercise_id, set_index)` 제약과 `rewards`의 사용자/운동 유일 제약이 중복 입력을 막습니다.
- 제약 충돌은 공통 `409 CONFLICT`로 변환됩니다. 세트 중복처럼 API에서 확인 가능한 충돌은 구체 오류 코드로 먼저 반환합니다.

`expectedVersion`은 운동 시작 응답과 세트/운동 이동 응답의 `version` 값으로 갱신합니다. 모든 쓰기 경로에 행 잠금과 DB 제약을 함께 두어 요청이 서로 다른 API 인스턴스에 도착해도 DB가 최종 일관성을 보장하게 합니다.
